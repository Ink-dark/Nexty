# ADR: JSRT 引擎选型（rquickjs / QuickJS-NG）与 `Document` !Send 架构定案

- 日期：2026-10-31（K5 T0 任务卡）；侦察与定稿 2026-11-01
- 状态：已采纳
- 任务依据：[批次 2 goal 泳道 A T0](../plans/2026-10-31-round-batch2-parallel.md)；硬约束见
  `AGENTS.md` Hard Rules（JSRT 可插拔、许可证白名单、不造轮子、依赖类型不入 pub API）；
  unsafe 口径按用户指令 2026-10-31（kernel facade crate 维持 forbid，runner 适配 crate 允许）。
- 侦察方法：本地证据（代码 / perf 基线 / 批次 1 执行报告）→ 联网调研（crates.io API、
  官方站、test262.fyi、quickjs-ng 仓库）→ MSVC 探针实证（探针工程在
  `.workbuddy/t-k5-recon/probe/`，不入库；全程未跑 repo 内 cargo）。数据快照日期 2026-11-01。

## 决策（三项全有结论）

1. **引擎：`rquickjs`（绑定 QuickJS-NG）**。runner 适配 crate 定名 `nexty-jsrt-rquickjs`
   （T2 落地为 workspace 新 member）。
2. **`Document` !Send：维持现状**——Send 数据面 + 主线程建 Document，接受每次导航两次解析；
   「注册表外置换 Send」否决（理由与重估触发条件见下）。
3. **unsafe 边界**：kernel 各 facade crate 维持 `#![forbid(unsafe_code)]`；runner 适配 crate
   允许 unsafe，仅限与引擎 C API 的 FFI 适配面，每处附 SAFETY 注释并在本 ADR 记录边界；
   AGENTS Hard Rules 措辞修订随 T4 登记（本 ADR 不改 AGENTS.md）。

## 为什么是 rquickjs（三条定案理由）

1. **依赖足迹与构建成本**：28 vs 171 包（6 倍差）、check 元数据 110 vs 298 MiB、
   MSVC check 15.8s vs 51.6s。K5 只需 script eval + 绑定 + 微任务泵，无需 Boa
   「纯 Rust 无 C 工具链」的优势——该优势在本机已被探针消解（cc/cl.exe 编译
   quickjs-ng 0.16.2 一次通过）。
2. **维护节奏与生态先例**：2026 年 rquickjs 发版 5 次且 API 已自述 feature complete；
   quickjs-ng 被 AWS LLRT（rquickjs README 社区段）、R 的 QuickJSR、vcpkg 采信，
   长期停摆风险低。
3. **绑定面与 unsafe 边界**：rquickjs-core 提供 safe wrapper API，适配 crate 的自有
   unsafe 面最小（raw FFI 留在 rquickjs-sys 第三方内部，我们只写适配层）；user classes
   + opaque userdata 与「arena DOM 不与引擎 GC 深度耦合」的选型要求吻合。

Boa 保留为可插拔备选：接缝 trait 在 nexty-dom（feature `jsrt`），换引擎只需重写适配 crate。

## 为什么不是别的

- **Boa**：唯一进入终局的候选，差距仅在依赖足迹 / MSVC 构建 / 发版节奏（见对比表），
  非许可证或合规问题。
- **rusty_v8 / deno_core**：默认构建从 GitHub releases 下载预编译静态库（二进制 blob，
  供应链与离线构建死角）；源码构建需 gn/ninja/clang，官方 README 自述 V8 为
  600k+ 行 C++、编译 30 分钟以上；运行时面向 Deno；DOM 绑定需对接 V8 堆。拒绝。
- **Kiesel**：MIT 许可（无许可证问题）、test262.fyi 94.8%，但为 **Zig** 实现——无
  Rust crate，接入需自写 C ABI 绑定并引入 zig 工具链，且官方自述「still at an early
  stage」。拒绝。
- **原版 QuickJS（bellard）**：上游休眠，quickjs-ng README 自述即为此而 fork；
  rquickjs 已绑 ng。
- **Hermes / Nova**（test262.fyi 41.8% / 76.9%）：全量 conformance 与 K5 语义基线
  差距明显。拒绝。

## `Document` !Send 决策：维持现状（Send 数据面 + 主线程建 Document）

证据链：

- !Send 根源：`Document.listeners: ListenerRegistry`（`crates/nexty-dom/src/tree.rs:67`）
  持 `Box<dyn EventListener>`（`crates/nexty-dom/src/event/mod.rs:224,246`）。
- 两次解析位置：后台规划解析（`crates/nexty-chrome/src/resources.rs` `fetch_page_data`
  ——规划 Document 收集子资源清单后即弃）+ 主线程按同一 HTML 重建正式 Document
  （`crates/nexty-chrome/src/app.rs:599-604` `parse_document`）。
- 成本量化：首屏 parse 在 perf 基线三场景为 21.4 / 93.2 / 0.1 ms
  （`docs/2026-10-25-perf-baseline.md` 首屏表）；主线程重建发生在子资源网络 settle 之后，
  即导航关键路径净增一次 parse（上述量级）；规划 Document 不驻留内存。相对网络 RTT
  与 cascade/layout（数百 ms 级）是小头。
- 否决「注册表外置」的核心理由：K5 之后页面与 JS 引擎上下文同生共死，而两候选引擎的
  Context/Runtime 均 !Send（探针编译证据，E0277）——把 ListenerRegistry 迁出 Document
  换来的 Document Send，并不能让「装配好的页面」跨线程搬运；且监听器即将持有 JS 函数值
  （同样 !Send），!Send 属性只是从 Document 挪到外置注册表；外置还要拆 K1 的
  TaskContext / dispatch 所有权接口（结构性「不重入」保证被重排）。收益归零、成本为正。
- 重估触发条件：未来实测中 parse 在导航瓶颈里占比显著（如超深页面 html5ever 平方
  复杂度恶化，见 AGENTS.md nexty-html 段），或出现真正的后台/离屏 DOM 需求（worker、
  预渲染）。

## unsafe 边界声明

- kernel facade crates（含 nexty-dom 新 `jsrt` feature 面）：维持 `#![forbid(unsafe_code)]`；
  接缝 trait 与绑定注册表零 unsafe，引擎类型不入 pub API（Hard Rules）。
- 新 runner 适配 crate `nexty-jsrt-rquickjs`：允许 unsafe，边界 = 与 QuickJS C API 的
  FFI 适配点；rquickjs-core 已提供 safe wrapper，预期自有 unsafe 极少；每处 unsafe
  附 SAFETY 注释，模块文档登记边界清单。
- AGENTS.md Hard Rules 措辞修订（「禁 unsafe 限定 kernel facade crate；runner 适配
  crate 允许 unsafe 并须在 ADR 记录边界」）随 T4 登记，本轮不编辑 AGENTS.md。

## deny.toml 影响清单（runner crate 引入时执行，本轮不改 deny.toml）

- 直接依赖：`rquickjs` / `rquickjs-core` / `rquickjs-sys` / `rquickjs-macro`（均 0.14.0，MIT）。
- 传递依赖合计 28 包，许可表达式 6 种：`MIT`、`MIT OR Apache-2.0`、`Apache-2.0 OR MIT`、
  `(MIT OR Apache-2.0) AND Unicode-3.0`、`Unlicense OR MIT`、`Zlib`——全部落在现有
  白名单（OR 析取支存在白名单成员即判定通过），**deny.toml 无需改动**。
- vendored quickjs-ng 0.16.2 的 C 源随 rquickjs-sys 分发（树内 LICENSE = MIT），不构成
  独立依赖项，不单独入 about 清单（cargo-about 按 crate 计）。
- 备查（若未来重评 Boa）：boa 树 171 包、12 个许可表达式（含 `LGPL-2.1-or-later`、
  `Unlicense OR MIT`），同样全部在白名单内。

## MSVC 构建结论（探针实测，2026-11-01）

环境：Windows x86_64-pc-windows-msvc，cargo/rustc 1.98.1，registry 经 rsproxy 镜像；
探针工程 `D:\Nexty\.workbuddy\t-k5-recon\probe\`（不入库，自带 `[workspace]` 隔离，
全程未触碰 repo 内任何 crate 的构建）。

| 探针 | 干净 check | build+link+实跑 | 实跑输出 | 依赖数 | check 元数据 |
| --- | --- | --- | --- | --- | --- |
| probe-rquickjs（features: classes/properties/array-buffer/loader/macro） | 15.8 s | 9.5 s | `eval 1+1 = 2`、`eval str = ab` ✓ | 28 包 | 109.5 MiB / 302 文件 |
| probe-boa（boa_engine + boa_runtime，default features） | 51.6 s | 70.5 s | `JsValue(Integer32(2))`、`JsValue(String("ab"))` ✓ | 171 包 | 297.8 MiB / 1454 文件 |

- 两引擎在 MSVC 上均可构建、可链接、可运行；rquickjs README 对 windows-msvc 标注的
  「experimental」风险被探针消解（cl.exe 编译 quickjs-ng 0.16.2 一次通过）。
- 探针另以 `fn assert_send<T: Send>()` 静态断言拿到两引擎 Context/Runtime 的 !Send
  编译级证据（E0277 错误文本存 T0-report）。
