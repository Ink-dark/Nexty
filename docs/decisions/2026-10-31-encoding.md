# ADR: 主文档字符编码探测选用 `encoding_rs`

- 日期：2026-10-31
- 状态：已采纳
- 背景：主文档此前用严格 `String::from_utf8` 解码，GBK / Shift_JIS 等非 UTF-8
  页面直接解码失败进错误页。需要 WHATWG Encoding Standard 的编码标签表与
  解码器，按「HTTP charset > BOM > meta 预扫 > UTF-8」四层优先级探测。导航
  与网络完备轮（network 0.1.5 → 0.1.6）T2 落地（本 ADR 只覆盖 network 层的
  解码入口；chrome 侧接线为 T5）。

## 候选

| 候选 | 许可证 | 结论 |
| --- | --- | --- |
| `encoding_rs` 0.8.42 | MIT OR Apache-2.0 | **采纳**。Firefox 维护的 WHATWG Encoding Standard 实现，标签表（`Encoding::for_label` 覆盖 `gbk` / `gb2312` / `shift_jis` 等全部标准标签）与解码器（替换字符语义、BOM 剥离）开箱即用；已是依赖树成员（reqwest 的 charset feature 传递依赖），直依赖化**零新增包** |
| `chardetng` | MIT OR Apache-2.0 | 否决（本轮）：它是无元数据时的编码**自动探测**；本轮优先级链由 goal 固定，探测层不存在。后续若加「无任何提示时探测」再评估并另记 ADR |
| 自研编码表 + 解码器 | — | 否决：GBK / GB18030 等编码表体量巨大且语义细节（替换、BOM、UTF-16 字节序）正是「有成熟轮子不自己造」的典型 |

## 决策

1. **依赖接线**：`decode = ["dep:encoding_rs"]`，独立 feature，不依赖 fetch
   （纯字节 + 头值输入）。
2. **解码入口**：`nexty_network::decode_document(content_type: Option<&str>,
   body: &[u8]) -> DecodedDocument`（自有类型，`encoding_rs` 类型不外泄），
   返回文本与实际采用编码名（`&'static str`，encoding_rs 规范名）。
3. **优先级链**（goal 固定）：HTTP header `Content-Type` 的 `charset` 参数 >
   BOM（UTF-8 / UTF-16LE / UTF-16BE）> `<meta charset>` / http-equiv 预扫
   （前 1024 字节，WHATWG HTML §13.2.3.5 的简化档）> 默认 UTF-8。每层未知
   标签视同未命中落到下一层。
4. **HTTP 层用无 BOM 处理解码**：`Encoding::decode` 自带 BOM 嗅探并可覆盖
   所选编码，违反 HTTP > BOM 的优先级，故 HTTP 层走
   `decode_without_bom_handling`，解码后剥掉前导 U+FEFF（BOM 字节不进文本）。
5. **边界**：只解码不编码；样式表不在本层解码（chrome 简化档：按文档解码
   结果或 UTF-8，lossy 兜底）；不实现规范的用户显式覆盖、父浏览上下文继承、
   自动探测等步骤。

## 偏差清单

- 预扫是 WHATWG §13.2.3.5 的简化档：识别 `<meta charset>` 与
  `<meta http-equiv=content-type content=…charset=…>`（属性顺序无关、跳过
  注释 / DOCTYPE / bogus comment），不实现完整字节级 prescan 状态机；
- HTTP 指定编码与 BOM 编码族不同时（如 charset=GBK 而字节流带 UTF-8 BOM），
  BOM 字节按该编码解出为杂字，不做特殊处理；
- 与 WHATWG HTML §13.2.3 完整算法的步骤差异（用户覆盖、父上下文继承、
  窗口自动探测）不实现——本轮按 goal 的固定链执行。

## 许可证与依赖面

- `encoding_rs`（MIT OR Apache-2.0）在 `deny.toml` 白名单内；本就在依赖树
  （reqwest 传递），直依赖化不新增包，deny / about 产出无实质变化（批次收口
  时按流程重跑并重新注入）。

## 验证

- `cargo test -p nexty-network --no-default-features --features decode`：20 条
  单测覆盖四层优先级矩阵（HTTP 胜 BOM / 胜 meta、BOM 三族、meta 引号 / 无引
  号 / 1024 窗口 / 注释遮蔽 / 多 meta 首个已知标签胜出、非法字节替换、
  Content-Type 解析用例）+ 1 条 doc test；
- 非法字节路径不 panic（替换字符兜底）由
  `invalid_bytes_are_replaced_without_panic` 钉住；
- GBK 页实机渲染（chrome T5 退出条件）待接线后验收。
